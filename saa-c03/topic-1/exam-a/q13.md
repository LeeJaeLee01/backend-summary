# Q13 — Multi-Region RDS credential rotation

## Question

**EN:** A company performs monthly maintenance on its AWS infrastructure. During these maintenance activities, the company needs to rotate the credentials for its Amazon RDS for MySQL databases across multiple AWS Regions. Which solution will meet these requirements with the LEAST operational overhead?

**VI:** Một công ty thực hiện **bảo trì hàng tháng** hạ tầng AWS. Trong kỳ bảo trì, công ty cần **rotate credential** cho **Amazon RDS for MySQL** trên **nhiều AWS Region**. Giải pháp nào đáp ứng yêu cầu với **ít overhead vận hành nhất**?

---

## Options

### A

**EN:** Store the credentials as secrets in AWS Secrets Manager. Use multi-Region secret replication for the required Regions. Configure Secrets Manager to rotate the secrets on a schedule.

**VI:** Lưu credential trong **Secrets Manager**. **Multi-Region secret replication**. Cấu hình **rotation theo lịch**.

### B

**EN:** Store the credentials as secrets in AWS Systems Manager by creating a secure string parameter. Use multi-Region secret replication for the required Regions. Configure Systems Manager to rotate the secrets on a schedule.

**VI:** Lưu trong **Systems Manager Parameter Store** (SecureString). Multi-Region replication. Rotation theo lịch.

### C

**EN:** Store the credentials in an Amazon S3 bucket that has server-side encryption (SSE) enabled. Use Amazon EventBridge (Amazon CloudWatch Events) to invoke an AWS Lambda function to rotate the credentials.

**VI:** Lưu credential trên **S3** (SSE). **EventBridge** invoke **Lambda** rotate.

### D

**EN:** Encrypt the credentials as secrets by using AWS Key Management Service (AWS KMS) multi-Region customer managed keys. Store the secrets in an Amazon DynamoDB global table. Use an AWS Lambda function to retrieve the secrets from DynamoDB. Use the RDS API to rotate the secrets.

**VI:** **KMS multi-Region** + **DynamoDB global table** + **Lambda** retrieve/rotate qua RDS API.

---

## Answer

**Đáp án: A**

**Note:** Rotate RDS credential **multi-Region** với ít vận hành → **Secrets Manager** + **multi-Region replication** + **scheduled rotation** tích hợp RDS — không cần Lambda tự viết.

| Option | Vì sao loại / chọn |
|--------|---------------------|
| **A ✅** | **Secrets Manager** hỗ trợ **multi-Region replication** + **scheduled rotation** tích hợp RDS — managed, ít code/vận hành nhất. |
| B | Parameter Store **không** có multi-Region secret replication + RDS rotation native như Secrets Manager. |
| C | Tự build Lambda rotate — overhead cao, dễ lỗi. |
| D | DynamoDB + Lambda + KMS — over-engineered, nhiều moving parts. |

**Ghi nhớ:** RDS credential rotation multi-Region → **Secrets Manager replication + schedule**.
