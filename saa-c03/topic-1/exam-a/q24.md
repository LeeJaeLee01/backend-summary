# Q24 — Analyze EC2 cost spike by instance type

## Question

**EN:** A company observes an increase in Amazon EC2 costs in its most recent bill. The billing team notices unwanted vertical scaling of instance types for a couple of EC2 instances. A solutions architect needs to create a graph comparing the last 2 months of EC2 costs and perform an in-depth analysis to identify the root cause of the vertical scaling. How should the solutions architect generate the information with the LEAST operational overhead?

**VI:** Bill **EC2** tăng; phát hiện **vertical scaling** instance type không mong muốn. Cần **biểu đồ so sánh 2 tháng** + phân tích root cause. Cách nào **ít overhead vận hành nhất**?

---

## Options

### A

**EN:** Use AWS Budgets to create a budget report and compare EC2 costs based on instance types.

**VI:** Dùng **AWS Budgets** tạo budget report so sánh EC2 theo instance type.

### B

**EN:** Use Cost Explorer's granular filtering feature to perform an in-depth analysis of EC2 costs based on instance types.

**VI:** Dùng **Cost Explorer** filter chi tiết phân tích EC2 cost theo instance type.

### C

**EN:** Use graphs from the AWS Billing and Cost Management dashboard to compare EC2 costs based on instance types for the last 2 months.

**VI:** Dùng graph **Billing and Cost Management dashboard** so sánh EC2 2 tháng theo instance type.

### D

**EN:** Use AWS Cost and Usage Reports to create a report and send it to an Amazon S3 bucket. Use Amazon QuickSight with Amazon S3 as a source to generate an interactive graph based on instance types.

**VI:** **Cost and Usage Reports** → S3 → **QuickSight** graph interactive.

---

## Answer

**Đáp án: B**

| Option | Vì sao loại / chọn |
|--------|---------------------|
| A | **Budgets** = alert/threshold — không phải công cụ phân tích chi tiết root cause theo dimension. |
| **B ✅** | **Cost Explorer** built-in: filter theo service, instance type, time range 2 tháng, graph + drill-down — **ít setup nhất** cho cost analysis. |
| C | Billing dashboard cơ bản — ít granular hơn Cost Explorer cho deep dive instance type. |
| D | CUR + QuickSight — powerful nhưng **overhead** setup pipeline, không “least overhead”. |

**Ghi nhớ:** Phân tích chi phí AWS theo dimension → **Cost Explorer**.
