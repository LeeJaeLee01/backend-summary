# Q3 — S3 access limited to AWS Organization members

## Question

**EN:** A company uses AWS Organizations to manage multiple AWS accounts for different departments. The management account has an Amazon S3 bucket that contains project reports. The company wants to limit access to this S3 bucket to only users of accounts within the organization in AWS Organizations. Which solution meets these requirements with the LEAST amount of operational overhead?

**VI:** Một công ty dùng **AWS Organizations** để quản lý nhiều AWS account theo từng phòng ban. Management account có một **S3 bucket** chứa báo cáo dự án. Công ty muốn **giới hạn truy cập** bucket này chỉ cho user thuộc các account **trong organization**. Giải pháp nào đáp ứng yêu cầu với **ít chi phí vận hành nhất**?

---

## Options

### A

**EN:** Add the `aws:PrincipalOrgID` global condition key with a reference to the organization ID to the S3 bucket policy.

**VI:** Thêm global condition key **`aws:PrincipalOrgID`** (tham chiếu organization ID) vào **S3 bucket policy**.

### B

**EN:** Create an organizational unit (OU) for each department. Add the `aws:PrincipalOrgPaths` global condition key to the S3 bucket policy.

**VI:** Tạo **organizational unit (OU)** cho mỗi phòng ban. Thêm global condition key **`aws:PrincipalOrgPaths`** vào S3 bucket policy.

### C

**EN:** Use AWS CloudTrail to monitor the `CreateAccount`, `InviteAccountToOrganization`, `LeaveOrganization`, and `RemoveAccountFromOrganization` events. Update the S3 bucket policy accordingly.

**VI:** Dùng **AWS CloudTrail** theo dõi các event `CreateAccount`, `InviteAccountToOrganization`, `LeaveOrganization`, `RemoveAccountFromOrganization`. Cập nhật S3 bucket policy tương ứng.

### D

**EN:** Tag each user that needs access to the S3 bucket. Add the `aws:PrincipalTag` global condition key to the S3 bucket policy.

**VI:** Gắn **tag** cho từng user cần truy cập S3 bucket. Thêm global condition key **`aws:PrincipalTag`** vào S3 bucket policy.

---

## Answer

**Đáp án: A**

| Option | Vì sao loại / chọn |
|--------|---------------------|
| **A ✅** | `aws:PrincipalOrgID` trong bucket policy = chỉ principal thuộc organization đó mới access. **Một lần cấu hình**, tự động áp dụng mọi account trong org — ít vận hành nhất. |
| B | `PrincipalOrgPaths` + OU từng department — phức tạp hơn khi đề chỉ cần “trong organization”, không cần phân OU. |
| C | CloudTrail + cập nhật policy thủ công/reactive — overhead cao, dễ trễ và lỗi. |
| D | Tag từng user — không scale, phải maintain tag liên tục khi user/account thay đổi. |

**Ví dụ bucket policy (ý tưởng):**

```json
{
  "Condition": {
    "StringEquals": {
      "aws:PrincipalOrgID": "o-xxxxxxxxxx"
    }
  }
}
```
