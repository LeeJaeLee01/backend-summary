# Q25 — Lambda + Aurora: decouple ingest and DB load

## Question

**EN:** A company is designing an application. The application uses an AWS Lambda function to receive information through Amazon API Gateway and to store the information in an Amazon Aurora PostgreSQL database. During the proof-of-concept stage, the company has to increase the Lambda quotas significantly to handle the high volumes of data that the company needs to load into the database. A solutions architect must recommend a new design to improve scalability and minimize the configuration effort. Which solution will meet these requirements?

**VI:** App: **API Gateway → Lambda → Aurora PostgreSQL**. POC phải tăng **Lambda quota** mạnh vì volume load DB cao. Cần thiết kế mới **scale tốt hơn**, **ít cấu hình**. Giải pháp nào phù hợp?

---

## Options

### A

**EN:** Refactor the Lambda function code to Apache Tomcat code that runs on Amazon EC2 instances. Connect the database by using native Java Database Connectivity (JDBC) drivers.

**VI:** Refactor Lambda sang **Tomcat trên EC2**, JDBC nối DB.

### B

**EN:** Change the platform from Aurora to Amazon DynamoDB. Provision a DynamoDB Accelerator (DAX) cluster. Use the DAX client SDK to point the existing DynamoDB API calls at the DAX cluster.

**VI:** Đổi **Aurora → DynamoDB** + **DAX** cluster.

### C

**EN:** Set up two Lambda functions. Configure one function to receive the information. Configure the other function to load the information into the database. Integrate the Lambda functions by using Amazon Simple Notification Service (Amazon SNS).

**VI:** **2 Lambda**: nhận data + load DB. Tích hợp bằng **SNS**.

### D

**EN:** Set up two Lambda functions. Configure one function to receive the information. Configure the other function to load the information into the database. Integrate the Lambda functions by using an Amazon Simple Queue Service (Amazon SQS) queue.

**VI:** **2 Lambda**: nhận data + load DB. Tích hợp bằng **SQS queue**.

---

## Answer

**Đáp án: D**

| Option | Vì sao loại / chọn |
|--------|---------------------|
| A | EC2 + Tomcat — tăng ops, không giải quyết decouple ingest vs DB write. |
| B | Đổi sang DynamoDB — thay đổi data model lớn, không “minimal config” nếu đã chọn Aurora. |
| C | **SNS** push — không buffer burst; consumer scale kém hơn SQS cho load DB. |
| **D ✅** | **Decouple**: API Lambda nhận → **SQS buffer** → worker Lambda ghi Aurora. Scale consumer độc lập, giảm concurrent API Lambda, không cần tăng quota đồng thời. |

**Ghi nhớ:** API nhanh + DB write nặng → **SQS giữa 2 Lambda**.
