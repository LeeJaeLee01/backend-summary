# Q10 — Ecommerce orders processed in receive order

## Question

**EN:** A company is building an ecommerce web application on AWS. The application sends information about new orders to an Amazon API Gateway REST API to process. The company wants to ensure that orders are processed in the order that they are received. Which solution will meet these requirements?

**VI:** Một công ty đang xây **ứng dụng ecommerce** trên AWS. Ứng dụng gửi thông tin đơn hàng mới tới **Amazon API Gateway REST API** để xử lý. Công ty muốn đảm bảo các đơn hàng được xử lý **đúng thứ tự nhận**. Giải pháp nào đáp ứng yêu cầu này?

---

## Options

### A

**EN:** Use an API Gateway integration to publish a message to an Amazon Simple Notification Service (Amazon SNS) topic when the application receives an order. Subscribe an AWS Lambda function to the topic to perform processing.

**VI:** API Gateway publish message lên **SNS topic** khi nhận order. **Lambda** subscribe topic để xử lý.

### B

**EN:** Use an API Gateway integration to send a message to an Amazon Simple Queue Service (Amazon SQS) FIFO queue when the application receives an order. Configure the SQS FIFO queue to invoke an AWS Lambda function for processing.

**VI:** API Gateway gửi message tới **SQS FIFO queue** khi nhận order. Cấu hình FIFO queue **invoke Lambda** xử lý.

### C

**EN:** Use an API Gateway authorizer to block any requests while the application processes an order.

**VI:** Dùng **API Gateway authorizer** chặn mọi request trong lúc app đang xử lý một order.

### D

**EN:** Use an API Gateway integration to send a message to an Amazon Simple Queue Service (Amazon SQS) standard queue when the application receives an order. Configure the SQS standard queue to invoke an AWS Lambda function for processing.

**VI:** API Gateway gửi message tới **SQS standard queue**. Standard queue invoke **Lambda** xử lý.

---

## Answer

**Đáp án: B**

**Note:** Cần xử lý đơn hàng **đúng thứ tự nhận** → chọn **SQS FIFO queue** + Lambda; SNS và SQS Standard không đảm bảo ordering.

| Option | Vì sao loại / chọn |
|--------|---------------------|
| A | **SNS** fan-out — **không đảm bảo ordering** giữa các message. |
| **B ✅** | **SQS FIFO** = **strict ordering** trong message group + exactly-once processing (dedup). Phù hợp “xử lý đúng thứ tự nhận”. |
| C | Authorizer chặn request — **không scale**, không phải queue ordering pattern. |
| D | **SQS Standard** = best-effort ordering — **không** đảm bảo thứ tự. |

**Ghi nhớ:** Cần thứ tự → **SQS FIFO** (+ `MessageGroupId` nếu partition theo customer/order).
