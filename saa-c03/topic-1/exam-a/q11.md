# Q11 — Minimize credential management for Aurora

## Question

**EN:** A company has an application that runs on Amazon EC2 instances and uses an Amazon Aurora database. The EC2 instances connect to the database by using user names and passwords that are stored locally in a file. The company wants to minimize the operational overhead of credential management. What should a solutions architect do to accomplish this goal?

**VI:** Một công ty có ứng dụng chạy trên **Amazon EC2 instances** và dùng **Amazon Aurora database**. EC2 kết nối DB bằng **username/password lưu trong file local**. Công ty muốn **giảm tối đa overhead** quản lý credential. **Solutions architect** nên làm gì để đạt mục tiêu này?

---

## Options

### A

**EN:** Use AWS Secrets Manager. Turn on automatic rotation.

**VI:** Dùng **AWS Secrets Manager**. Bật **automatic rotation**.

### B

**EN:** Use AWS Systems Manager Parameter Store. Turn on automatic rotation.

**VI:** Dùng **AWS Systems Manager Parameter Store**. Bật **automatic rotation**.

### C

**EN:** Create an Amazon S3 bucket to store objects that are encrypted with an AWS Key Management Service (AWS KMS) encryption key. Migrate the credential file to the S3 bucket. Point the application to the S3 bucket.

**VI:** Tạo **S3 bucket** mã hóa KMS, chuyển file credential lên S3, app đọc từ S3.

### D

**EN:** Create an encrypted Amazon Elastic Block Store (Amazon EBS) volume for each EC2 instance. Attach the new EBS volume to each EC2 instance. Migrate the credential file to the new EBS volume. Point the application to the new EBS volume.

**VI:** Tạo **EBS volume** mã hóa cho mỗi EC2, chuyển file credential sang EBS.

---

## Answer

**Đáp án: A**

**Note:** Credential DB đang hardcode trong file trên EC2 → chuyển sang **AWS Secrets Manager** + **auto rotation**, app lấy secret qua API với IAM role — không cần maintain file/password thủ công.

| Option | Vì sao loại / chọn |
|--------|---------------------|
| **A ✅** | **Secrets Manager** — lưu secret, tích hợp RDS/Aurora, **rotation tự động**, app lấy qua SDK/API. IAM role EC2 — không file plaintext. |
| B | Parameter Store lưu secret được (`SecureString`) nhưng **rotation native cho RDS** là điểm mạnh **Secrets Manager**; ít overhead hơn cho use case DB credential. |
| C | S3 vẫn phải tự rotate, quản lý access — overhead cao hơn Secrets Manager. |
| D | EBS per instance — vẫn file tĩnh, không auto rotation, scale EC2 khó sync. |

**Pattern:** EC2 + RDS/Aurora → **IAM instance profile** + **Secrets Manager** (rotation).
