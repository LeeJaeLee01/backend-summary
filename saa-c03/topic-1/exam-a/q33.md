# Q33 — Financial transactions: near-real-time, PII removal, DynamoDB

## Question

**EN:** A company runs an online marketplace web application on AWS. The application serves hundreds of thousands of users during peak hours. The company needs a scalable, near-real-time solution to share the details of millions of financial transactions with several other internal applications. Transactions also need to be processed to remove sensitive data before being stored in a document database for low-latency retrieval. What should a solutions architect recommend to meet these requirements?

**VI:** Marketplace online, peak **hàng trăm nghìn user**. Cần giải pháp **scale**, **gần real-time** chia sẻ **hàng triệu giao dịch tài chính** cho nhiều app nội bộ. Phải **loại dữ liệu nhạy cảm** trước khi lưu **document database** (low-latency). Giải pháp nào phù hợp?

---

## Options

### A

**EN:** Store the transactions data into Amazon DynamoDB. Set up a rule in DynamoDB to remove sensitive data from every transaction upon write. Use DynamoDB Streams to share the transactions data with other applications.

**VI:** Lưu **DynamoDB**, rule tự xóa sensitive khi write, **DynamoDB Streams** chia sẻ app khác.

### B

**EN:** Stream the transactions data into Amazon Kinesis Data Firehose to store data in Amazon DynamoDB and Amazon S3. Use AWS Lambda integration with Kinesis Data Firehose to remove sensitive data. Other applications can consume the data stored in Amazon S3.

**VI:** **Kinesis Data Firehose** → DynamoDB + S3, **Lambda** xóa sensitive, app khác đọc **S3**.

### C

**EN:** Stream the transactions data into Amazon Kinesis Data Streams. Use AWS Lambda integration to remove sensitive data from every transaction and then store the transactions data in Amazon DynamoDB. Other applications can consume the transactions data off the Kinesis data stream.

**VI:** **Kinesis Data Streams** → **Lambda** xóa sensitive → **DynamoDB**. App khác consume trực tiếp **Kinesis stream**.

### D

**EN:** Store the batched transactions data in Amazon S3 as files. Use AWS Lambda to process every file and remove sensitive data before updating the files in Amazon S3. The Lambda function then stores the data in Amazon DynamoDB. Other applications can consume transaction files stored in Amazon S3.

**VI:** Batch file **S3** → **Lambda** xóa sensitive → DynamoDB. App khác đọc **S3**.

---

## Answer

**Đáp án: C**

| Option | Vì sao loại / chọn |
|--------|---------------------|
| A | DynamoDB **không có** “rule xóa sensitive on write” built-in; ingest hàng triệu txn peak khó chỉ DynamoDB write. |
| B | Firehose + S3 consumer — **không near-real-time** bằng Kinesis Streams cho multi-consumer. |
| **C ✅** | **Kinesis Data Streams** scale ingest hàng triệu; **Lambda** transform/xóa PII; **DynamoDB** low-latency store; consumer khác đọc **trực tiếp stream** = near-real-time fan-out. |
| D | Batch S3 files — latency cao, không đáp ứng near-real-time. |

**Ghi nhớ:** Stream ingest + multi-consumer real-time + transform + NoSQL → **Kinesis Streams + Lambda + DynamoDB**.
