# Q14 — Auto-scale database reads with high availability

## Question

**EN:** A company runs an ecommerce application on Amazon EC2 instances behind an Application Load Balancer. The instances run in an Amazon EC2 Auto Scaling group across multiple Availability Zones. The Auto Scaling group scales based on CPU utilization metrics (chỉ số sử dụng). The ecommerce application stores the transaction data in a MySQL 8.0 database that is hosted on a large EC2 instance. The database's performance degrades quickly as application load increases. The application handles more read requests than write transactions. The company wants a solution that will automatically scale the database to meet the demand of unpredictable read workloads while maintaining high availability. Which solution will meet these requirements?

**VI:** Một công ty chạy **ứng dụng ecommerce** trên **EC2** sau **Application Load Balancer**. Instance nằm trong **EC2 Auto Scaling group** trên **nhiều Availability Zone**, scale theo **CPU**. Ứng dụng lưu giao dịch trên **MySQL 8.0** chạy trên **một EC2 instance lớn** — performance DB giảm nhanh khi load tăng. App **đọc nhiều hơn ghi**. Công ty cần giải pháp **tự động scale database** cho read workload **không dự đoán được**, vẫn đảm bảo **high availability**. Giải pháp nào phù hợp?

---

## Options

### A

**EN:** Use Amazon Redshift with a single node for leader and compute functionality.

**VI:** Dùng **Amazon Redshift** single node (leader + compute).

### B

**EN:** Use Amazon RDS with a Single-AZ deployment. Configure Amazon RDS to add reader instances in a different Availability Zone.

**VI:** **RDS Single-AZ**, thêm **reader** ở AZ khác.

### C

**EN:** Use Amazon Aurora with a Multi-AZ deployment. Configure Aurora Auto Scaling with Aurora Replicas.

**VI:** **Amazon Aurora Multi-AZ**. **Aurora Auto Scaling** với **Aurora Replicas**.

### D

**EN:** Use Amazon ElastiCache for Memcached with EC2 Spot Instances.

**VI:** **ElastiCache Memcached** + **EC2 Spot**.

---

## Answer

**Đáp án: C**

**Note:** MySQL trên EC2 không scale read, workload read-heavy và biến đổi → **Aurora Multi-AZ** + **read replicas** + **Aurora Auto Scaling** — tự thêm/bớt replica theo load, vẫn HA.

| Option | Vì sao loại / chọn |
|--------|---------------------|
| A | **Redshift** = data warehouse/analytics — không thay OLTP MySQL ecommerce transactions. |
| B | **Single-AZ** không HA; reader RDS thường gắn Multi-AZ cluster — đề bài mô tả sai/không đủ. |
| **C ✅** | **Aurora** compatible MySQL, **replicas** scale read, **Auto Scaling** replicas theo load, **Multi-AZ** HA — đúng pattern read-heavy ecommerce. |
| D | Memcached cache layer — không thay DB scale + HA; Spot EC2 không giải quyết DB bottleneck. |

**Ghi nhớ:** Read-heavy + unpredictable + HA → **Aurora + read replicas + Auto Scaling**.
