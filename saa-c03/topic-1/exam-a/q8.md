# Q8 — Modernize job coordinator to resilient scalable architecture

## Question

**EN:** A company is migrating a distributed application to AWS. The application serves variable workloads. The legacy platform consists of a primary server that coordinates jobs across multiple compute nodes. The company wants to modernize the application with a solution that maximizes resiliency and scalability. How should a solutions architect design the architecture to meet these requirements?

**VI:** Công ty migrate app phân tán lên AWS. Workload **biến đổi**. Legacy: **primary server** điều phối job cho nhiều **compute node**. Muốn hiện đại hóa để **resiliency** và **scalability** tối đa. Kiến trúc nên thiết kế thế nào?

---

## Options

### A

**EN:** Configure an Amazon Simple Queue Service (Amazon SQS) queue as a destination for the jobs. Implement the compute nodes with Amazon EC2 instances that are managed in an Auto Scaling group. Configure EC2 Auto Scaling to use scheduled scaling.

**VI:** **SQS** làm đích job. Compute node = **EC2 Auto Scaling**. Scale theo **scheduled scaling**.

### B

**EN:** Configure an Amazon Simple Queue Service (Amazon SQS) queue as a destination for the jobs. Implement the compute nodes with Amazon EC2 instances that are managed in an Auto Scaling group. Configure EC2 Auto Scaling based on the size of the queue.

**VI:** **SQS** làm đích job. Compute = **EC2 Auto Scaling**. Scale theo **độ dài queue (backlog)**.

### C

**EN:** Implement the primary server and the compute nodes with Amazon EC2 instances that are managed in an Auto Scaling group. Configure AWS CloudTrail as a destination for the jobs. Configure EC2 Auto Scaling based on the load on the primary server.

**VI:** Primary + compute trên **EC2 ASG**. **CloudTrail** làm đích job. Scale theo load primary server.

### D

**EN:** Implement the primary server and the compute nodes with Amazon EC2 instances that are managed in an Auto Scaling group. Configure Amazon EventBridge (Amazon CloudWatch Events) as a destination for the jobs. Configure EC2 Auto Scaling based on the load on the compute nodes.

**VI:** Primary + compute trên **EC2 ASG**. **EventBridge** làm đích job. Scale theo load compute nodes.

---

## Answer

**Đáp án: B**

| Option | Vì sao loại / chọn |
|--------|---------------------|
| A | **Scheduled scaling** — cố định theo lịch, không khớp **variable workload**. |
| **B ✅** | **SQS** thay primary coordinator — decouple, durable buffer. **ASG scale theo queue depth** = thêm worker khi backlog tăng — pattern worker pool chuẩn. |
| C | **CloudTrail** = audit API — không phải job queue. Vẫn giữ primary server SPOF. |
| D | EventBridge không thay job queue cho workload dạng job backlog; vẫn có primary server. |

**Ghi nhớ:** Job queue + worker ASG → scale metric **`ApproximateNumberOfMessagesVisible`** (SQS).
