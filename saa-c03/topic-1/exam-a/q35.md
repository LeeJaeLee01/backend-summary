# Q35 — DDoS protection for public web app behind ELB

## Question

**EN:** A company is preparing to launch a public-facing web application in the AWS Cloud. The architecture consists of Amazon EC2 instances within a VPC behind an Elastic Load Balancer (ELB). A third-party service is used for the DNS. The company's solutions architect must recommend a solution to detect and protect against large-scale DDoS attacks. Which solution meets these requirements?

**VI:** Web app **public**, **EC2 + VPC + ELB**. DNS dùng **bên thứ ba** (không Route 53). Cần **phát hiện và bảo vệ DDoS quy mô lớn**. Giải pháp nào phù hợp?

---

## Options

### A

**EN:** Enable Amazon GuardDuty on the account.

**VI:** Bật **Amazon GuardDuty**.

### B

**EN:** Enable Amazon Inspector on the EC2 instances.

**VI:** Bật **Amazon Inspector** trên EC2.

### C

**EN:** Enable AWS Shield and assign Amazon Route 53 to it.

**VI:** Bật **AWS Shield** và gán **Route 53**.

### D

**EN:** Enable AWS Shield Advanced and assign the ELB to it.

**VI:** Bật **AWS Shield Advanced** và gán **ELB**.

---

## Answer

**Đáp án: D**

| Option | Vì sao loại / chọn |
|--------|---------------------|
| A | **GuardDuty** = threat detection (anomaly) — không inline DDoS mitigation cho ELB. |
| B | **Inspector** = vulnerability scan EC2 — không chống DDoS. |
| C | DNS **third-party** — không dùng Route 53; Shield Standard free tự động cho CloudFront/Route53 nhưng không cover ELB advanced. |
| **D ✅** | **Shield Advanced** — DDoS protection **lớn**, 24/7 DRT, gắn **protected resources** (ELB, CloudFront, Route 53). Đúng “large-scale DDoS” + ELB architecture. |

**Ghi nhớ:** Large-scale DDoS + ELB → **Shield Advanced** (+ thường kèm WAF). DNS third-party → không chọn Route 53 option.
