# Q2 — Analyze JSON logs in S3

## Question

**EN:** A company needs the ability to analyze the log files of its proprietary application. The logs are stored in JSON format in an Amazon S3 bucket. Queries will be simple and will run on-demand. A solutions architect needs to perform the analysis with minimal changes to the existing architecture. What should the solutions architect do to meet these requirements with the LEAST amount of operational overhead?

**VI:** Một công ty cần khả năng phân tích log files của ứng dụng độc quyền. Các log đang được lưu ở định dạng **JSON** trong một **Amazon S3 bucket**. Các truy vấn sẽ đơn giản và chạy theo nhu cầu (on-demand). Một solutions architect cần thực hiện phân tích với thay đổi tối thiểu đối với kiến trúc hiện tại. Giải pháp nào đáp ứng yêu cầu này với **ít chi phí vận hành nhất**?

---

## Options

### A

**EN:** Use Amazon Redshift to load all the content into one place and run the SQL queries as needed.

**VI:** Dùng **Amazon Redshift** để nạp toàn bộ dữ liệu vào một nơi, rồi chạy truy vấn SQL khi cần.

### B

**EN:** Use Amazon CloudWatch Logs to store the logs. Run SQL queries as needed from the Amazon CloudWatch console.

**VI:** Dùng **Amazon CloudWatch Logs** để lưu logs. Chạy truy vấn SQL khi cần từ CloudWatch console.

### C

**EN:** Use Amazon Athena directly with Amazon S3 to run the queries as needed.

**VI:** Dùng **Amazon Athena** trực tiếp trên **Amazon S3** để chạy truy vấn khi cần.

### D

**EN:** Use AWS Glue to catalog the logs. Use a transient Apache Spark cluster on Amazon EMR to run the SQL queries as needed.

**VI:** Dùng **AWS Glue** để tạo catalog cho logs. Dùng cụm **Apache Spark tạm thời trên Amazon EMR** để chạy truy vấn SQL khi cần.

---

## Answer

**Đáp án: C**

**Note:** Logs JSON đã nằm sẵn trên S3, chỉ cần query đơn giản on-demand với ít thay đổi kiến trúc → chọn **Athena** vì query trực tiếp trên S3, serverless, không cần ingest hay quản lý cluster.

| Option | Vì sao loại / chọn |
|--------|---------------------|
| A | Redshift cần ingest/ETL và quản trị cluster/warehouse, quá nặng cho truy vấn đơn giản on-demand. |
| B | CloudWatch Logs Insights phù hợp log trong CloudWatch; ở đây logs đã nằm trong S3 JSON. Chuyển nơi lưu log làm tăng thay đổi kiến trúc. |
| **C ✅** | Athena query trực tiếp dữ liệu trong S3 theo mô hình serverless, không cần quản lý hạ tầng, phù hợp truy vấn đơn giản và on-demand, thay đổi kiến trúc tối thiểu. |
| D | Glue + EMR Spark vận hành phức tạp hơn nhiều so với nhu cầu đơn giản. |
