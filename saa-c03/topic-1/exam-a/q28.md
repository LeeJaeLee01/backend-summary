# Q28 — SSO across Organizations + on-premises AD

## Question

**EN:** A company is migrating applications to AWS. The applications are deployed in different accounts. The company manages the accounts centrally by using AWS Organizations. The company's security team needs a single sign-on (SSO) solution across all the company's accounts. The company must continue managing the users and groups in its on-premises self-managed Microsoft Active Directory. Which solution will meet these requirements?

**VI:** Một công ty migrate ứng dụng lên AWS, triển khai trên **nhiều account khác nhau**, quản lý tập trung bằng **AWS Organizations**. Team security cần **SSO (single sign-on)** trên **tất cả account**. Công ty phải **tiếp tục quản lý users và groups** trong **Microsoft Active Directory on-premises** (self-managed). Giải pháp nào phù hợp?

---

## Options

### A

**EN:** Enable AWS Single Sign-On (AWS SSO) from the AWS SSO console. Create a one-way forest trust or a one-way domain trust to connect the company's self-managed Microsoft Active Directory with AWS SSO by using AWS Directory Service for Microsoft Active Directory.

**VI:** Bật **AWS SSO** (IAM Identity Center). Tạo **one-way forest/domain trust** nối AD on-prem với SSO qua **AWS Directory Service for Microsoft AD**.

### B

**EN:** Enable AWS Single Sign-On (AWS SSO) from the AWS SSO console. Create a two-way forest trust to connect the company's self-managed Microsoft Active Directory with AWS SSO by using AWS Directory Service for Microsoft Active Directory.

**VI:** Bật **AWS SSO**. **Two-way forest trust** với AD on-prem qua Managed Microsoft AD.

### C

**EN:** Use AWS Directory Service. Create a two-way trust relationship with the company's self-managed Microsoft Active Directory.

**VI:** **Directory Service** + **two-way trust** AD on-prem (không nêu SSO).

### D

**EN:** Deploy an identity provider (IdP) on premises. Enable AWS Single Sign-On (AWS SSO) from the AWS SSO console.

**VI:** Deploy **IdP on-premises** + bật **AWS SSO**.

---

## Answer

**Đáp án: A**

**Note:** Multi-account SSO + giữ AD on-prem làm nguồn user → **IAM Identity Center (AWS SSO)** + **one-way trust** với **Managed Microsoft AD** — không cần sync user sang AWS thủ công.

| Option | Vì sao loại / chọn |
|--------|---------------------|
| **A ✅** | **IAM Identity Center (SSO)** + **Organizations** = SSO multi-account. **One-way trust** on-prem AD → **Managed Microsoft AD** = user/group vẫn quản lý on-prem, SSO vào AWS — pattern chuẩn SAA. |
| B | Two-way trust — không bắt buộc, phức tạp hơn one-way cho use case này. |
| C | Chỉ Directory Service trust — thiếu **SSO across accounts** rõ ràng. |
| D | IdP on-prem mơ hồ — không mô tả tích hợp AD + Organizations đầy đủ. |

**Ghi nhớ:** Multi-account SSO + giữ AD on-prem → **IAM Identity Center + Managed AD + one-way trust**.
