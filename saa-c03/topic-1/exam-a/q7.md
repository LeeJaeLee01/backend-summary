# Q7 — Decouple ingestion with burst to 100k msg/s

## Question

**EN:** A company has an application that ingests incoming messages. Dozens of other applications and microservices then quickly consume these messages. The number of messages varies drastically and sometimes increases suddenly to 100,000 each second. The company wants to decouple the solution and increase scalability. Which solution meets these requirements?

**VI:** Ứng dụng **ingest message**; hàng chục app/microservice **consume** ngay sau đó. Số message **biến động mạnh**, đôi khi tăng đột ngột **100.000/giây**. Công ty muốn **decouple** và tăng **scalability**. Giải pháp nào phù hợp?

---

## Options

### A

**EN:** Persist the messages to Amazon Kinesis Data Analytics. Configure the consumer applications to read and process the messages.

**VI:** Lưu message vào **Amazon Kinesis Data Analytics**. Consumer đọc và xử lý.

### B

**EN:** Deploy the ingestion application on Amazon EC2 instances in an Auto Scaling group to scale the number of EC2 instances based on CPU metrics.

**VI:** Deploy app ingest trên **EC2 Auto Scaling** theo metric CPU.

### C

**EN:** Write the messages to Amazon Kinesis Data Streams with a single shard. Use an AWS Lambda function to preprocess messages and store them in Amazon DynamoDB. Configure the consumer applications to read from DynamoDB to process the messages.

**VI:** Ghi vào **Kinesis Data Streams** (1 shard), **Lambda** preprocess → **DynamoDB**, consumer đọc từ DynamoDB.

### D

**EN:** Publish the messages to an Amazon Simple Notification Service (Amazon SNS) topic with multiple Amazon Simple Queue Service (Amazon SQS) subscriptions. Configure the consumer applications to process the messages from the queues.

**VI:** Publish lên **SNS topic**, nhiều **SQS subscription**. Consumer xử lý từ từng queue.

---

## Answer

**Đáp án: D**

| Option | Vì sao loại / chọn |
|--------|---------------------|
| A | **Kinesis Data Analytics** = xử lý stream SQL/Flink — không phải message bus decouple producer/consumer. |
| B | Scale EC2 ingest — **không decouple** producer/consumer; consumer vẫn phụ thuộc ingest. |
| C | **1 shard Kinesis** ≈ ~1 MB/s hoặc ~1000 records/s — **không chịu 100k/s**; thêm bottleneck DynamoDB. |
| **D ✅** | **SNS fan-out + SQS queue mỗi consumer** = decouple, buffer burst, scale consumer độc lập — pattern chuẩn microservices. |

**Ghi nhớ:** 1 event → N consumer + buffer → **SNS → SQS (mỗi service 1 queue)**.
