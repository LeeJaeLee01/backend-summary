# Q5 — ALB + EBS: users see different documents

## Question

**EN:** A company is hosting a web application on AWS using a single Amazon EC2 instance that stores user-uploaded documents in an Amazon EBS volume. For better scalability and availability, the company duplicated the architecture and created a second EC2 instance and EBS volume in another Availability Zone, placing both behind an Application Load Balancer. After completing this change, users reported that, each time they refreshed the website, they could see one subset of their documents or the other, but never all of the documents at the same time. What should a solutions architect propose to ensure users see all of their documents at once?

**VI:** Công ty host web app trên **một EC2** lưu tài liệu user upload trên **EBS volume**. Để tăng scalability và availability, họ nhân đôi kiến trúc: thêm EC2 + EBS ở **AZ khác**, đặt sau **Application Load Balancer**. Sau khi đổi, user báo mỗi lần refresh chỉ thấy **một phần** tài liệu — không bao giờ thấy **tất cả** cùng lúc. Solutions architect nên đề xuất gì để user luôn thấy đủ tài liệu?

---

## Options

### A

**EN:** Copy the data so both EBS volumes contain all the documents.

**VI:** Copy dữ liệu để **cả hai EBS volume** đều chứa toàn bộ tài liệu.

### B

**EN:** Configure the Application Load Balancer to direct a user to the server with the documents.

**VI:** Cấu hình ALB **định tuyến user** tới server có tài liệu của họ.

### C

**EN:** Copy the data from both EBS volumes to Amazon EFS. Modify the application to save new documents to Amazon EFS.

**VI:** Copy dữ liệu từ cả hai EBS sang **Amazon EFS**. Sửa app để **lưu tài liệu mới lên EFS**.

### D

**EN:** Configure the Application Load Balancer to send the request to both servers. Return each document from the correct server.

**VI:** Cấu hình ALB **gửi request tới cả hai server**, trả từng tài liệu từ server đúng.

---

## Answer

**Đáp án: C**

**Note:** Hai EC2 + hai EBS sau ALB → mỗi lần refresh user chỉ thấy data trên một máy (EBS không share giữa instance) → chọn **EFS**: shared file system multi-AZ, cả hai EC2 mount chung và lưu file mới lên EFS để luôn thấy đủ tài liệu.

| Option | Vì sao loại / chọn |
|--------|---------------------|
| A | Sync 2 EBS thủ công — không scale, upload mới chỉ vào 1 volume, vẫn lệch dữ liệu. |
| B | ALB không sticky theo “user owns which files on which server” — không giải quyết shared storage. |
| **C ✅** | **EBS gắn 1 EC2** — không share giữa instance. **EFS** = NFS managed, **multi-AZ**, nhiều EC2 mount chung → mọi request thấy cùng dataset. |
| D | ALB không merge response từ 2 backend — không phải pattern hợp lệ. |

**Ghi nhớ:** Stateless app + shared files → **EFS** hoặc **S3**, không replicate EBS giữa AZ.
