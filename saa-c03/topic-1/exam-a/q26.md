# Q26 — Detect unauthorized S3 bucket configuration changes

## Question

**EN:** A company needs to review its AWS Cloud deployment to ensure that its Amazon S3 buckets do not have unauthorized configuration changes. What should a solutions architect do to accomplish this goal?

**VI:** Công ty cần đảm bảo **S3 bucket** không bị **thay đổi cấu hình trái phép**. Làm gì?

---

## Options

### A

**EN:** Turn on AWS Config with the appropriate rules.

**VI:** Bật **AWS Config** với **rules** phù hợp.

### B

**EN:** Turn on AWS Trusted Advisor with the appropriate checks.

**VI:** Bật **AWS Trusted Advisor** với checks phù hợp.

### C

**EN:** Turn on Amazon Inspector with the appropriate assessment template.

**VI:** Bật **Amazon Inspector** với assessment template.

### D

**EN:** Turn on Amazon S3 server access logging. Configure Amazon EventBridge (Amazon CloudWatch Events).

**VI:** Bật **S3 server access logging** + **EventBridge**.

---

## Answer

**Đáp án: A**

| Option | Vì sao loại / chọn |
|--------|---------------------|
| **A ✅** | **AWS Config** ghi nhận **configuration changes** (bucket policy public, encryption off…) và **rules** tự đánh giá compliance — đúng “unauthorized configuration changes”. |
| B | Trusted Advisor = recommendations best practice — không continuous config audit như Config. |
| C | Inspector = vulnerability assessment EC2/container — không audit S3 bucket config. |
| D | Access logging = ai **truy cập object**, không phải **thay đổi cấu hình bucket**. |

**Ghi nhớ:** Resource config compliance → **AWS Config rules** (`s3-bucket-public-read-prohibited`, …).
