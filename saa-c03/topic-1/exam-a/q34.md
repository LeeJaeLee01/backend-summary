# Q34 — Configuration changes vs API call history

## Question

**EN:** A company hosts its multi-tier applications on AWS. For compliance, governance, auditing, and security, the company must track configuration changes on its AWS resources and record a history of API calls made to these resources. What should a solutions architect do to meet these requirements?

**VI:** Vì **compliance, governance, audit, security**, công ty phải **theo dõi thay đổi cấu hình** resource AWS và **ghi lại lịch sử API calls** tới các resource đó. Làm gì?

---

## Options

### A

**EN:** Use AWS CloudTrail to track configuration changes and AWS Config to record API calls.

**VI:** **CloudTrail** = config changes; **Config** = API calls.

### B

**EN:** Use AWS Config to track configuration changes and AWS CloudTrail to record API calls.

**VI:** **AWS Config** = config changes; **CloudTrail** = API calls.

### C

**EN:** Use AWS Config to track configuration changes and Amazon CloudWatch to record API calls.

**VI:** **Config** = config changes; **CloudWatch** = API calls.

### D

**EN:** Use AWS CloudTrail to track configuration changes and Amazon CloudWatch to record API calls.

**VI:** **CloudTrail** = config changes; **CloudWatch** = API calls.

---

## Answer

**Đáp án: B**

| Option | Vì sao loại / chọn |
|--------|---------------------|
| A | **Đảo ngược** — CloudTrail = API calls, Config = configuration state/changes. |
| **B ✅** | **AWS Config** — snapshot & history **resource configuration** (compliance). **CloudTrail** — log **who called which API** (audit trail). |
| C | **CloudWatch** = metrics/logs/alarms — không phải API audit trail đầy đủ như CloudTrail. |
| D | CloudTrail không thay Config cho configuration drift tracking. |

**Ghi nhớ:**

```
Config     → WHAT changed on resources (configuration)
CloudTrail → WHO did WHAT API call WHEN
```
